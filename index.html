Zona 1 · Assistido

Níveis 1 e 2

a IA acelera, você decide tudo
1Tab Complete2021 →
Autocomplete que sugere a próxima linha ou bloco. Você continua fazendo 100% das decisões; a IA só encurta a digitação.
Sinais de que você está aqui
  • Aceita sugestões inline, nunca "conversa" com a IA
  • Ganho real em boilerplate e código repetitivo
  • Zero mudança no processo do time
Ferramentas típicas
GitHub Copilot (inline)Cursor TabWindsurf / CodeiumJetBrains AI
Destrava o próximo: dar ao agente permissão para ler o repositório, editar vários arquivos e rodar comandos.
2Agent IDE2024 →
Um agente lê o repo, edita múltiplos arquivos, roda testes e comandos — no IDE ou no terminal. É aqui que o vibe coding acontece: rápido para protótipos, frágil em produção.
Sinais de que você está aqui
  • Pede features em linguagem natural e aceita diffs sem ler
  • Repete o mesmo contexto a cada prompt novo
  • Resultado varia muito de dev para dev
Ferramentas típicas
CursorClaude CodeCodex CLICopilot agent modeGemini CLIWindsurf
Destrava o próximo: parar de repetir contexto — escrever, uma vez e versionado, o que o agente precisa saber.
⚠️O ganho aparece no protótipo; o custo aparece no segundo mês: código que ninguém entende, testes ausentes, contexto perdido a cada sessão.
📊80% dos novos devs no GitHub usam Copilot já na primeira semana (Octoverse 2025) — os níveis 1–2 viraram commodity.
Zona 2 · Estruturado

Níveis 3 e 4

o repositório vira o cérebro do agente
3Context Engineering2025 →
Projetar deliberadamente o que entra na janela de contexto — regras, arquitetura, convenções, exemplos — e o que fica de fora. O prompt deixa de ser improviso e vira artefato do repo. Lema do autor: "every token needs to fight for its place in the prompt".
Sinais de que você está aqui
  • AGENTS.md / CLAUDE.md / rules versionados e revisados em PR
  • Docs curados para o agente, não só para humanos
  • Onboarding de um agente novo leva minutos, não dias
Ferramentas e padrões
AGENTS.md (padrão aberto)CLAUDE.mdCursor Rulescopilot-instructions.mdllms.txtspec.md
Destrava o próximo: fazer cada tarefa deixar o repositório mais fácil para a próxima — contexto que se acumula em vez de evaporar.
4Compounding Engineering2025 →
Loop Plan → Work → Review → Codify: cada tarefa termina codificando a lição (spec, teste, regra, ADR) em arquivos que toda sessão futura lê. Pular o "codify" é só engenharia tradicional com IA — o ganho composto vem daí.
Sinais de que você está aqui
  • Specs versionadas antes do código; testes como contrato
  • Erros de review viram regra escrita, não conversa perdida
  • Velocidade sobe com o tempo em vez de cair
Ferramentas e padrões
Spec Kit (GitHub)Kiro specs (AWS)ADRsmemória de projetoCompounding Engineering (Every)
Destrava o próximo: conectar o agente ao mundo fora do repo — sistemas, dados e ferramentas da empresa.
📐Spec-Driven Development mora aqui. A spec é contexto explícito (nível 3) que se acumula e compõe (nível 4). É a ponte entre "vibe" e engenharia.
Zona 3 · Instrumentado

Níveis 5 e 6

o agente vira sistema — com controles
5MCP & Skillsnov/2024 →
O agente ganha ferramentas padronizadas (Model Context Protocol) e procedimentos reutilizáveis (Skills): acessa Jira, bancos, observabilidade, deploy — em vez de adivinhar.
Sinais de que você está aqui
  • Servidores MCP internos para os sistemas da empresa
  • Skills versionadas por time (deploy, review, runbooks)
  • O agente consulta a fonte de verdade, não a memória do modelo
Ferramentas e padrões
MCP (Anthropic → Linux Foundation)Agent SkillsMCP RegistryMCP servers internos
Destrava o próximo: tratar o agente como software em produção — com permissões, medição e limites.
6Harness Engineering2026 →
A engenharia ao redor do modelo: permissões, sandboxes, guardrails, evals, observabilidade, custo e loops de feedback mecânicos (lint, testes, CI). "Give the agent the feedback loop, not just the editor." Não é prompt engineering com outro nome.
Sinais de que você está aqui
  • Evals antes de trocar modelo ou prompt
  • Métricas: custo por tarefa, taxa de PR aceito, retrabalho
  • Hooks que bloqueiam ações perigosas; ambientes isolados
Ferramentas e padrões
hooks & permissõessandboxesevals (Promptfoo, Braintrust, LangSmith)OpenTelemetrycircuit breakers
Destrava o próximo: soltar o agente sem você olhando — porque o harness olha por você.
🧰Nível 6 é onde a maioria das empresas trava: exige disciplina de plataforma, não só ferramenta nova.
📊5 milhões de usuários semanais no Codex (jun/2026) e 41% das orgs de software com MCP em produção (Stacklok 2026): harness virou infraestrutura.
Zona 4 · Autônomo

Níveis 7 e 8

humano por exceção, não por linha
7Background Agents2025 →
Agentes exploram, planejam e implementam de forma assíncrona, sem aprovação prévia do plano, enquanto o time faz outra coisa. Um orquestrador central roteia trabalho para vários agentes e modelos em paralelo. Precisam de spec clara e harness para funcionar.
Sinais de que você está aqui
  • Issue → PR sem ninguém abrir o IDE
  • Agentes disparados por eventos (CI falhou, alerta, cron)
  • Vários agentes em paralelo, cada um no seu ambiente
Ferramentas típicas
Codex (cloud)Copilot coding agentGoogle JulesDevinClaude Code (web / cloud)Cursor background agents
Destrava o próximo: o orquestrador central vira gargalo — os agentes precisam coordenar-se diretamente entre si.
8Autonomous Agent Teamsfronteira
Agentes coordenam-se diretamente entre si — reivindicam tarefas, compartilham descobertas, sinalizam dependências e resolvem conflitos — sem passar tudo por um orquestrador central. O humano aprova marcos e decide escopo, não linhas.
Sinais de que você está aqui
  • Dezenas de agentes simultâneos na mesma base de código
  • O gargalo é conflito e coordenação, não "um orquestrador"
  • Governança: quem responde pelo que foi entregue?
Ferramentas típicas
Claude Code Agent Teams (preview · fev/2026)Claude Agent SDKDevin Desktop (multi-agente via ACP)AutoGen · CrewAI
O que falta: o próprio autor não define um nível 9. Modelos ainda lentos e caros para isso; o gargalo é confiança, governança e custo — multiagente consome ~15× os tokens de um chat.
🚀Poucas empresas operam no 8 fora de produtos de IA. Mas o nível 7 já é rotina em 2026 para quem construiu os níveis 3–6 antes.
📊1M+ PRs abertos pelo Copilot coding agent em 5 meses (Octoverse 2025). Multiagente: +90% de desempenho a ~15× o custo em tokens (Anthropic).

Spec-Driven Development

O que ganha, onde dói, onde encaixa.

O que ganha

  • contratoCritérios de aceite antes do código — a IA não "adivinha" o escopo
  • memóriaContexto sobrevive à sessão, ao dev e à troca de modelo
  • paraleloTarefas independentes → vários agentes ao mesmo tempo
  • 35 / 15features por sprint com 1/4 do time (piloto AI-DLC)
  • 6 engem 76 dias, onde se estimava 40 por 1 ano (Bedrock + Kiro)
  • reviewRevisão desloca-se de linhas de código para intenção e risco

Onde dói

  • ▲Overhead em mudanças pequenas — spec de 4 páginas para um bug de 3 linhas
  • ▲Spec drift: sem validação contínua, a spec vira documento morto
  • ▲Garbage in: spec ambígua gera código errado com mais convicção
  • ▲Waterfall disfarçado se a spec tenta prever tudo de uma vez (Scott Logic)
  • ▲~4h vs ~32 min na mesma tarefa pequena — o overhead é real (Scott Logic)
  • ▲Ainda "Assess" no Radar da Thoughtworks (nov/2025) — não é "Adopt"
  • ▲Ainda precisa de review — a spec reduz, não elimina, a verificação

Onde encaixa na escada

7 Background Agents exige spec
6 Harness Engineering spec = eval
5 MCP & Skills
4 Compounding Engineering SDD compõe
3 Context Engineering SDD nasce
2 Agent IDE

Leitura desta palestra: SDD é a prática mais barata para sair do nível 2. E é pré-requisito para os níveis 6–7: sem spec não há critério para eval, nem tarefa segura para um agente em background.

"We keep the generated code and delete the prompt…" — é como rasgar o código-fonte e versionar, com todo cuidado, o binário. A nova habilidade escassa é escrever a especificação que captura intenção e valores.— Sean Grove, OpenAI · "The New Code", AI Engineer World's Fair 2025 · fonte
Roadmap prático

Como subir um nível por trimestre.

1 → 2
Dê poder de edição
  • Adote um agent IDE / CLI com permissão de editar e rodar
  • Comece por testes e refactors, não por features
  • Combine: ninguém faz merge sem ler o diff
Métrica: % de PRs com assistência de agente
2 → 3
Escreva o contexto uma vez
  • AGENTS.md / CLAUDE.md na raiz: stack, convenções, comandos, o que não fazer
  • Docs de arquitetura curtos e atuais
  • Revise o contexto em PR como se fosse código
Métrica: retrabalho por tarefa caindo
3 → 4
Adote Spec-Driven
  • Spec por feature: o quê, por quê, critérios de aceite
  • Plan e tasks gerados e revisados antes do código
  • Lições de review viram regra escrita no repo
Métrica: acerto na 1ª tentativa
4 → 5
Conecte os sistemas
  • MCP servers para Jira, banco, observabilidade, docs
  • Skills reutilizáveis: deploy, runbook, review
  • Registro interno do que o agente pode acessar
Métrica: tarefas resolvidas sem humano buscar dado
5 → 6
Construa o harness
  • Permissões e sandbox por agente; hooks que bloqueiam ações perigosas
  • Evals com a spec como gabarito; custo por tarefa medido
  • Observabilidade: traces, tokens, taxa de aceite
Métrica: custo/tarefa e PRs aceitos sem alteração
6 → 7
Tire o agente do IDE
  • Agentes em CI: falhou o build → agente propõe fix
  • Issue com spec → PR em background
  • Fila de tarefas paralelas, cada uma no seu ambiente
Métrica: PRs merged originados por agente
7 → 8
Orquestre papéis
  • Agentes com papéis coordenando-se entre si, sem gargalo central
  • Contratos entre agentes (schemas, critérios) e revisão adversarial
  • Humano aprova marcos; auditoria completa
Métrica: incidentes por entrega autônoma
regra de ouro
Não pule degraus
  • Nível 7 sem 3–4 = agentes rápidos gerando lixo em paralelo
  • Nível 6 sem 5 = guardrails sem nada para proteger
  • Custo e risco sobem junto: multiagente ≈ 15× os tokens de um chat
  • Suba um nível, meça, e só então o próximo
